# UI、内置浏览器与 Projects V1

## 本轮目标

本轮将桌面端收敛为三栏工作台：左侧项目与任务、中间对话与输入、右侧执行信息或内置浏览器。设置使用宽幅双栏弹窗；首页不再展示“梳理项目 / 处理文件 / 检查代码”快捷卡片。

## Projects 数据模型

- **项目标识**：文件夹的规范化绝对路径，不另造数据库 ID。
- **任务归属**：Codex 运行时会话的 `cwd` 等于项目路径；`listSessions(projectPath)` 即该项目任务列表。
- **新建任务**：每次点击“新建任务”都先打开文件夹选择器；取消选择不会改变当前项目。
- **项目去重**：同一规范化路径只保留一个项目；最近选择的项目排在前面。
- **持久化**：`userData/projects.json` 只保存 `{version:1, paths:string[]}`，最多 100 个路径；个人版不引入 SQLite。
- **迁移**：首次启动时把既有 `settings.workspace` 加入项目表，保留原有任务历史。
- **会话切换**：选择项目后更新工作目录；选择任务时先切换项目，再读取对应会话历史。

## 设置界面

左侧分类为：通用、权限审批、MCP、模型、浏览器。右侧使用统一标题、说明、表格/分组卡片和开关样式。

- 模型：保留自定义 OpenAI/DeepSeek 兼容服务、API Key、测试与协议诊断。
- MCP：保留服务新增、编辑、启停、删除和工具目录刷新。
- 浏览器：管理内置浏览器启停、临时数据说明、默认浏览器及授权策略。
- 权限审批：明确浏览器单次/同类/任务完全授权及命令同类授权范围。

## 内置浏览器

右侧浏览器使用标签栏、导航按钮、圆角地址栏、接管按钮和诊断入口。网页仍由 Electron `WebContentsView` 渲染，UI 只是浏览器 chrome；不会依赖外部 Chrome。既有 HTTPS/回环 HTTP 策略、跨域资源授权、临时会话和任务审批边界保持不变。

## 验收标准

1. 两个不同文件夹各创建一个任务，侧栏显示两个项目且各有一个任务。
2. 项目和任务均可切换并恢复历史。
3. 首页快捷卡片不存在。
4. 模型、MCP、浏览器设置可以读取并完成原有操作。
5. 内置浏览器显示标签栏/地址栏，且 Agent 浏览、接管、资源授权回归通过。
