# 自定义模型服务（V1 增量）

## 使用

1. 启动桌面应用，打开侧栏「模型设置」→「新增模型服务」。
2. 填写服务名称、Base URL（如 https://example.com/v1）、服务商实际模型 ID。
3. 选择 Responses 或 Chat Completions，保存服务配置。
4. 为该服务单独保存 API Key，点击「测试」验证最小请求。
5. 关闭设置，在工作台顶部选择新模型，再提交任务。

仅 Responses/Chat Completions 兼容接口、Bearer API Key 方式；未实现匿名服务、OAuth、原生 Anthropic/Gemini 协议或自定义请求头。支持最多 20 个自定义条目，内置两个官方条目继续保留。

## 数据与边界

- `providers.json`：version=1，models 数组；每项保存 id/label/baseUrl/upstreamModel/protocol 及派生的凭据标识，不含密钥。复用 JsonStore 原子写入、有效备份及损坏恢复，设置页展示备份恢复提示。
- 内部 id 是自动生成的 `custom-<32位随机十六进制>`，与上游模型 ID 分离。Gateway 接收内部别名，转发时映射 upstreamModel。因此相同模型名可配置不同服务，无凭据串用。
- API Key 继续使用 safeStorage 密文。自定义条目的凭据文件、环境名称由内部 ID 派生，用户不能指定其他模型的密钥名称。
- HTTPS 可用于远程服务；HTTP 仅允许 localhost、127.0.0.1、[::1]。URL 拒绝用户信息、查询参数、fragment 和重复接口后缀。网络请求拒绝跳转。
- 新增/修改/删除时暂停空闲 Host，关闭旧 runtime，原子保存并重载注册表与凭据。正在运行或连接的任务阻止配置变更。
- 已有凭据时，仅名称可直接修改。修改地址、协议或模型前必须先删除凭据；通过环境变量注入的自定义凭据也需要先清除，再重启应用。
- 删除服务前必须切换到其他模型；待核对任务引用的服务不能删除。删除先清除密文，再移除配置；若配置写入失败，原条目仍保留但凭据已清除，可重新操作。
- 已删除服务若因注册表备份恢复而重新出现，其已删除密文不会恢复。设置引用缺失服务时回退 DeepSeek 并提示，不自动运行任务。
- 持久任务记录接受合法自定义 ID，删除服务不会使历史任务记录变成损坏配置。
- 主动关闭旧 runtime 的迟到关闭事件不再清空新连接状态。
