# 逐域资源授权（2026-09-22）

日常增量只修改源码、构建开发版并回归，不生成/覆盖安装包；安装验收时另行打包。

## 操作

1. 浏览器「站点诊断」显示被阻止的跨域资源。
2. 当前任务正在运行时先「接管」，等待正在执行的网页动作完成。
3. 对具体资源行选择「授权此资源类型」，核对完整 origin 和类型，二次确认。
4. 授权不会自动刷新；用户手动刷新后才重新加载页面。
5. 在已授权列表选择「撤销授权」并确认；再手动刷新验证。已运行的脚本及其副作用不被回滚。

只开放 `script / stylesheet / image / font`。域名授权严格包含 scheme、hostname、port，不包含子域，不授权 XHR、WebSocket、iframe、顶层导航或 popup。没有模型侧授权工具；网页自身没有应用 IPC。

## 生命周期与校验

- 只可授权当前诊断列表中实际被 cross-origin 策略阻止的具体 origin/type；不接受任意域名输入。
- 外部域名授权前检查 DNS 结果，拒绝私网；URL 凭据、路径、查询串及未知类型拒绝。
- 只有已经明确启用本机访问的本地页面，才可从诊断授权其他本机 origin。
- 最多 20 类授权；仅存于当前临时 session，不写盘。关闭页面或跨 origin 显式导航后清空；同 origin 刷新保留。
- 授权确认期间隐藏原生网页，避免网页覆盖确认界面。
- 等待 DNS 期间页面、操作代次或控制权变化会使授权失败。
- 更新授权会停止当前加载并作废元素引用与工具授权，不重放操作。
- 保持原站点 CSP、沙箱与权限限制；授权资源域不绕过站点自身 CSP。

DNS 预检查仍不等于连接 IP 固定，本次未实现完整 DNS rebinding 防护。脚本一旦获准运行，可以读取所在页面的数据；二次确认明确展示这一点。跨域资源授权不是对资源内容的信任认证。

## 验证

- 纯策略单测：origin/type 精确匹配、子域/端口隔离、URL 验证、容量上限、撤销、清空、返回副本。
- Electron 组件：初始拦截 → 图片授权 → 刷新加载 → 撤销 → 再次拦截，任务运行保护和 session 关闭清理。
- `npm run test:desktop:resources`：真实桌面按钮、二次确认、原生 view 隐藏、URL 脱敏、不自动刷新、允许/撤销/关闭。
- `npm run test:desktop:browser`：保留真实 Codex + Chat + MCP 浏览器链路。
