# CoAgent 对话驱动安全测试体系

日期：2026-09-23。适用：个人使用、低配置、低流量、不依赖扫描器。

## 1. 产品目标

从输入框「＋ → 使用插件 → 安全测试」启用专用模式。用户通过对话描述目标和目的，系统形成可读确认卡；确认后在既定范围内自主观察、提出假设、少量验证并留下证据。遇到凭据、验证码或高影响操作暂停，必要时交由用户在内置浏览器完成。

安全测试模式是 Host 的真实执行路径，不只是往普通 Agent 提示词中加一条说明。普通任务的 Shell/MCP/浏览器策略保持原样；安全测试模式只暴露经过范围控制和审计的工具。

## 2. 交互与范围

1. 选择安全测试模式，输入目标 URL、重点功能、测试目的。
2. 信息不足时对话补充，不要求填写配置 JSON。生成确认卡：目标、允许/排除范围、工具、登录方式、预算、暂停条件、审计位置。
3. 用户确认后冻结配置快照和哈希；后续扩大目标、端口、路径或行为类别需生成新的确认。
4. 测试期间展示状态、流量、证据和暂停/停止按钮。重启后保留记录，不自动重放未确认结果的请求。

目标规则与站点依赖分开：测试域名并不自动包含子域、第三方身份提供商和 CDN。允许登录或加载资源不等于允许验证该第三方。

## 3. 架构

```text
输入框 + 安全测试 / 对话 / 确认卡
                   |
       Security Session Controller
         |                         |
  Agent 规划与结果归纳          确认、预算、暂停状态
         |
  Tool Registry -> Scope Gate -> Budget Gate -> Audit intent
         |                                      |
  受控 HTTP Executor / Browser Adapter / Session Broker
         |
  请求、响应、重定向、失败 -> Audit Store -> Evidence -> Findings
```

### 三层审计

- 模型网关：模型请求元数据、响应状态、工具调用及结果关联、耗时。不默认记录密码或内部思维链。
- Host 工具边界：参数校验、范围判断、审批、预算消耗、实际执行和拒绝原因。
- 网络执行边界：真正发生的 HTTP 请求、响应和浏览器资源流量。模型网关本身看不到所有目标流量，不能替代该层。

统一关联：runId → turnId → toolCallId → requestId → evidenceId → findingId。发送前记录意图，完成后记录结果；缺失结果标记 unknown/partial，不据此假定未发送。

## 4. 低流量自主执行

观察页面/请求 → 建立功能与角色关系 → 提出一个具体假设 → 设计少量验证 → 比较响应 → 保存证据 → 排除、继续或暂停。

工具集合逐步增加：页面观察、受控 HTTP 请求、已记录流量查询、响应比较、用户接管、证据化发现。首版不使用扫描器、字典枚举和任意网络脚本。

建议完整版本默认：并发 1、主动验证约 1 请求/秒、首轮主动请求上限 100。页面及资源请求另设硬预算并单独计数，同时展示总请求/字节；不把浏览器资源当作“免费请求”。遇到限流、持续错误或性能恶化暂停。

GET 不天然等于无副作用；测试/验证动作按实际业务效果分类。账号变更、数据删除、支付、公开发布等需要具体确认。自动验证以足以证明或排除假设的最小证据为止，不扩大操作影响。

## 5. 浏览器与用户接管

状态：draft → awaiting-confirmation → running → waiting-for-user → user-takeover → verifying-session → running；终态 completed/failed/interrupted。

- 浏览器需要登录时暂停所有自动测试和页面控制。
- 用户接管期间停止向模型提供截图、DOM/可访问性快照、输入内容；不读取密码/验证码字段。
- 用户点击“登录完成，继续”后验证站点和会话状态，再恢复执行。
- Session Broker 保存本地会话，模型仅持有绑定任务、站点、角色、有效期的句柄。
- HTTP 工具只受控复用明确支持的会话；不把整个 Cookie 存储导出给模型。无法可靠迁移的状态保持在浏览器内操作。
- 第三方登录依赖独立确认，不把身份提供商加入测试范围。

### 浏览器采集实现

复用现有 Electron Session 和 debugger 连接。webRequest 处理请求生命周期、头、跳转和失败；CDP 补充可获取的正文与浏览器事件。统一管理监听器，避免多个 webRequest 同类监听器互相覆盖。采集能力必须针对当前捆绑 Electron/Chromium 版本验证。

缓存、流式响应、WebSocket、Worker、下载等明确记录采集覆盖情况；首版不支持的路径应禁止用于自动验证或暂停说明，不能静默留下审计缺口。记录是 HTTP 应用层视图，不宣称是 TLS/HTTP2 的原始线缆字节。暂不引入 HTTPS 中间人证书，减少用户配置。

## 6. 证据与敏感信息

两层存储：脱敏审计供界面/模型/默认导出；本地加密证据供人工复核，密钥交由系统凭据设施管理。不要把本机可读哈希链宣传为不可篡改签名。

每条请求记录：时间、任务/工具关联、来源、目标及实际地址、方法、头和正文保存状态、响应、跳转、耗时、角色句柄、范围/预算/审批决定、内容哈希与完整性状态。

登录密码、验证码和登录提交正文默认不保留原值；保留事件、结果与明确 redacted 标记。其他内容结合登录状态、字段和内容分类处理，不能只做字段名黑名单。导出默认脱敏，完整证据需人工明确选择。

“全程留痕”指全部动作有可关联记录；不意味着把凭据裸写日志，也不把截断、缺失或脱敏内容标作完整原始请求。

继续采用 JSONL + 分离证据文件，无需引入 SQLite：

```text
userData/security/<project-hash>/runs/<run-id>/
  plan.json             已确认目标、工具、预算、配置快照
  run.json              当前状态、计数、失败信息
  events.jsonl          时间线与完整性关联
  requests/             请求意图及采集记录
  evidence/             响应与证据
  findings.json         后续发现
  manifest.json         后续导出清单
```

先持久化请求意图，再发送；审计故障停止新增请求。磁盘满、权限变化、采集断连、请求中断、崩溃恢复都属于验收用例。文件大小/总容量到达上限时暂停，不悄悄丢证据。

## 7. 工具与出口边界

- Host 决定工具集合与执行权限；模型只提出计划。
- 请求参数、重定向、DNS 解析地址和每次重试重新检查范围，实际连接固定到校验地址。
- 安全模式不沿用普通 Agent 的任意 Shell/MCP 出网通道。真正接入模型循环前必须验证这些通道已关闭；单纯前端隐藏或提示词约束不算完成。
- 页面、响应、日志都作为不可信数据，不可变更范围、批准操作或索取本地机密。
- 普通 Agent 的任务级命令前缀授权不迁移到安全测试模式。

## 8. 分阶段计划与状态

| 阶段 | 目标 | 当前状态 |
|---|---|---|
| S1 | 范围、预算、确定性 HEAD、基础证据 | 已有 |
| S2-A | 输入框模式、目标草案、确认卡、单次计划、记录入口 | 本轮实现首版 |
| S2-B | 受控 HTTP 请求/正文审计、统一 ID、审计存储完整性、模型工具桥 | 待实现；本轮先补 HEAD 请求意图及关联 ID |
| S2-C | 浏览器请求正文采集、登录接管、Session Broker | 待实现 |
| S2-D | 证据驱动的自主验证循环、发现、报告与导出 | 待实现 |

### 本轮 S2-A 的准确范围

- 输入框「＋ → 使用插件 → 安全测试」不需要模型密钥。
- 用户输入包含一个明确 HTTP(S) URL 的句子；Host 从 URL 生成待确认草案，不调用模型推断自然语言约束。多 URL、URL 凭据/查询参数仍拒绝。
- 范围固定到指定主机、协议、端口和路径前缀，不自动放大为整站或所有子域。确认卡会显示原始说明和实际范围，用户可取消修改。
- 草案仅在 Host 内存保存，绑定项目、15 分钟有效、一次消费；新草案替换旧草案，重启失效。前端仅提交 id 和明确确认，不接受前端覆盖目标/预算。
- 采用保守 S1 预算：最多 30 请求（包括跳转）、1 请求/秒、并发 1、任务最多 60 秒。
- 确认后启动独立 HEAD 路径，不进入普通 Codex 运行时，不启动 Shell/MCP/浏览器；已有 S1 面板展示状态与证据。
- 持久化单次计划而不覆写项目 engagement.json；objective/draftId/profile 随计划保留。确认前零网络请求。
- 每个 HEAD 在 socket 请求前保存请求意图；响应证据包含相同 requestId；审计写入失败不发送该请求。此处并非完整线上报文字节采集，响应仍只保留 S1 选定响应头。
- 暂无模型自主渗透、全文正文审计、登录接管和自动漏洞判断。临时对话提示不并入普通 Codex 会话历史；安全计划和运行记录独立持久化。

## 9. 验收

1. 没确认/取消确认不产生目标流量；过期、跨项目和重复确认失效。
2. 前端篡改展示对象不改变 Host 保存的计划；新的无效草案也撤销旧草案。
3. 受控工具拒绝越界，审计失败零请求；停止后不发后续请求。
4. 请求意图、响应证据和计划关联一致；重启不重放。
5. 普通插件、附件、命令授权与 S1 回归不受影响。
6. S2-B/C/D 另补正文敏感信息、出网关闭、人工接管、浏览器复杂网络类型和发现证据的验收。

测试入口：`npm run check`、`npm run desktop:build`、`npm run test:desktop:security-draft`、`npm run test:desktop:security`、`npm run test:desktop:composer`。

## 10. 后续实现复用任务提示词

```text
按本设计逐阶段实现。模型只能提出工具调用，Host 决定范围与预算。
先保证每次实际出网经过执行和审计边界，再增加工具种类。
不把模型网关日志当成目标 HTTP 流量，不把请求意图当成实际已发送证明。
每项发现关联请求与响应证据；未知、脱敏、截断和采集缺口明确标注。

每一阶段补可重复的本地回归，明确完成项与尚未接入项，不默认打包安装包。
```

## S2-B 第一阶段：HTTP 响应与失败审计（已实现）

- 保持 HEAD-only，不新增扫描器、GET/POST、登录或模型自主循环。
- 每次收到响应都关联既有 requestId，保存状态码、HTTP 版本、响应头名称、脱敏后的值、毫秒耗时、正文未采集原因。HEAD 的正文明确标记 `not-collected`，不声称完整报文抓取。
- 仅保留 content-type/content-length/server/HSTS/nosniff/frame-options/cache-control/allow 的值（每项最多 1024 字符）；其他响应头值一律替换为 `[REDACTED]`，包括 Set-Cookie、认证头、自定义头和 Location。截断和脱敏字段清单随证据保存。允许保留的字段仍可能被服务端写入敏感内容，此机制不是任意内容的完美脱敏器。
- 重定向响应逐跳记录，Location 仅记录是否存在；执行器在内存中使用原值并继续执行已有范围校验。存储不保留 Location 路径、查询或片段。
- 网络断开、超时和在途取消生成 `network-error` / `aborted` 结果，包含标准错误码，不保存原始网络异常文本到该响应证据。请求意图、结果继续通过 requestId 关联；DNS、范围或审计失败发生在发送前时，仍由运行终态说明，不伪造已发出的请求。
- 响应审计失败立即结束，不继续重定向。崩溃窗口仍可能仅留下请求意图；意图不等于已成功发送。
- 本阶段不包含请求/响应正文、浏览器网络监听、模型网关审计和凭据代理；这些仍属后续 S2-B/C 工作。

回归：脱敏/截断、重定向逐跳、连接重置、超时、取消、审计失败阻止后续请求；全部使用本地 HTTP 夹具。
